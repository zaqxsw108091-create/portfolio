한계와 다음고쳐야 할 점을 알고 있습니다.

한계
  • 콘솔의 조치 표시는 4가지 공격 모두 "IP 차단" 하나로 통일했습니다. 계정 잠금은 연결되지 않았습니다.
  • 승인 화면에 로그인이 없어 승인자를 확인하지 못합니다.
  • 알림은 기록만 남고 메일·메신저로 보내지 않습니다.
  • 차단은 오탐 처리 때만 수동으로 풀립니다.
  • 공격은 간단한 방법으로 시연했습니다.
다시 한다면
  • 계정 잠금을 권한 회수 콘솔과 연결
  • 승인 화면에 로그인 추가
  • 알림을 실제로 발송
  • 차단 자동 해제 시간과 허용 목록 추가

최종 팀 코드는 DB 비밀번호와 방화벽 접속 키가 들어 있어 공개하지 않습니다.

캡스톤 초반 개인 실습: pfSense 방화벽 직접 구성

캡스톤 초반(2026.10.22~23)에 학원 PC의 VMware에 pfSense 방화벽을 직접 설치해 망의 기본 구성을 해 봤습니다. 최종 발표에는 망 구성을 전공한 조원이 만든 망을 썼습니다.

한 것
pfSense CE 2.9.0 설치, 인터페이스 6개(WAN, LAN, OPT1~OPT4)를 나누고, WAN은 DHCP로 받고 나머지 5개는 구역별 IP를 직접 설정, 외부 공개 구역(DMZ)에 취약 웹서버 DVWA(192.168.10.10) 구축
문제와 해결
호스트 PC와 pfSense의 IP가 겹쳐 접속이 안 되는 문제가 생겨, 호스트 쪽 IP를 192.168.20.5로 바꿔 해결
확인
WAN 쪽 Kali(192.168.100.130)에서 보낸 ping이 기본 규칙(Block private networks from WAN)에 막히는 것을 방화벽 로그로 확인
하지 못한 것
OPT1과 OPT2에는 패키지 설치용 임시 전체 허용 규칙만 넣었고, 구역별 보안 정책 규칙과 Kali에서 DVWA로의 공격, Wazuh 연동은 하지 못했습니다.

캡스톤 보안 콘솔 프로토타입

팀이 콘솔에 필요한 기능을 말로 먼저 정한 뒤, 제 파트를 먼저 끝낸 제가 제 코드와 임시 데이터로 Claude와 함께 만든 시험 버전입니다. AI에게 맡기되 사실은 바뀌지 않게 하는 장치를 넣었습니다. 정한 기능이 이렇게 나오는 게 맞는지, 기본 디자인은 이렇게 하면 어떨지 팀에 보여 주려고 만들었습니다. 이후 팀원들의 코드를 모두 합쳐 여러 번 수정하며, 기본 틀은 이어 가고 세부 디자인은 우주선 컨셉으로 바꿔 팀 최종 콘솔을 만들었습니다.

AI 보고서: 문장만 맡기고 사실은 코드가 지킨다

구조
사건 정보, 근거 로그, 조치 내역은 코드가 DB에서 그대로 가져와 규칙 기반 초안을 만듭니다. API 키가 있을 때만 AI가 문장을 다듬습니다.
검사
AI 결과에서 점수, IP, 시각, 제목이 바뀌었으면 그 결과를 버리고 초안을 씁니다.
키
API 키는 코드나 파일에 적지 않고 환경변수(ANTHROPIC_API_KEY)에서 읽습니다. AI를 켜면 로그가 외부로 나가므로 설정에서 끌 수 있게 했습니다.

한계 작업기록(2026.10.27) 시점에는 키가 없어 실제 AI 호출은 시험하지 못했고, 가짜 응답으로 검사 코드만 확인했습니다.

시험하다 찾아서 고친 것

문제
한글이 섞인 가짜 보안 토큰을 보내면 403 거부가 아니라 서버 오류(500)가 났습니다.
해결
두 값을 바이트로 바꿔 비교하게 고쳤고, 거부 기록이 감사 로그에 남는 것을 확인했습니다.
문제
AI가 점수를 바꿨는지 "90"으로 검사하면 다른 숫자 안의 90 때문에 통과할 수 있었습니다.
해결
"90점"처럼 단위까지 붙여 검사하게 고쳤습니다.

확인 자동 시험 56건 통과, 0건 실패. 로그인 5회 실패 시 10분 잠금, 허용 대역 밖 접속 차단, 원본 로그가 시험 전후로 바뀌지 않는 것(해시 비교)을 포함합니다.

AI와 일하는 방식

AI가 짠 것을 그대로 믿지 않고, 확인할 수 있는 형태로 만듭니다.

  1. 1단계내가 정한다무엇을 만들지, 어떤 기능을 넣고 뺄지 정합니다.
  2. 2단계AI가 짠다Claude(Claude Code), Codex, ChatGPT, Gemini에게 화면, 로직, 테스트 코드를 맡깁니다.
  3. 3단계테스트로 확인한다실행하고, 자동 테스트를 돌리고, 틀린 곳을 찾아 고치게 합니다. 최종 테스트는 직접 합니다.
  4. 4단계기록하고 한계를 적는다저장소에 "내가 정한 것, AI가 짠 것, 고친 것"과 한계를 나눠 남깁니다.

솔직하게 적습니다. 여기 있는 코드는 대부분 AI와 함께 만들었고, 제 C, Java, Python 문법은 기초 수준입니다. 캡스톤에서 처음 막힌 곳도 return, 딕셔너리, ==와 =의 차이 같은 기초였습니다. 그래서 프로젝트마다 직접 한 것과 AI와 함께 한 것, 한계를 나눠 적었습니다.
